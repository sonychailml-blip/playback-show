# Большой день импровизации в Батуми — страница playback.show/improvday

Отвечай по-русски. Пользователь — Михаил Чайлахян, музыкант и один из ведущих события.

## Что можно трогать

Работаем **только** с папкой `improvday/` (страница `improvday/index.html` и `improvday/media/`).
Остальное в репозитории — другие сайты (`index.html` — онлайн-курс плейбэка, `group/` — группа личных историй).
Их не менять, даже по ходу дела.

## Как выкладывается

- Репозиторий GitHub `sonychailml-blip/playback-show`, ветка `main`.
- Cloudflare (Worker со статикой) сам собирает и выкладывает сайт после каждого push в `main`, примерно за 1–2 минуты.
- Адрес страницы: https://playback.show/improvday/
- `.assetsignore` исключает из выкладки `.git`, `.assetsignore`, `CLAUDE.md`.
- Перед push проверить страницу локально (например, `python3 -m http.server` из корня репозитория и открыть `/improvday/`), на ширине телефона тоже: без горизонтальной прокрутки.

## Формы и таблица

- Форма заявки на интенсив отправляет POST (`mode:'no-cors'`) на Google Apps Script `FORM_URL` (в скрипте страницы). Поля: `what`, `name`, `contact`, `cur:'GEL'`, `tz`; скрытое поле-ловушка `website`.
- Заявки падают в Google-таблицу пользователя (лист «Заявки») с пометкой «ИМПРО · …» в колонке «Куда записался». Ту же таблицу используют другие сайты.
- Скрипт таблицы пишет колонки по названиям: Дата, Куда записался, Имя, Telegram / WhatsApp, Email, Валюта, Часовой пояс, Оплачено?. Значение `contact` попадает в «Telegram / WhatsApp». Код скрипта у пользователя; если понадобится новое поле, нужно дать ему обновлённый код и напомнить сделать «Новую версию» в «Управлении развёртываниями».

## Как работать с пользователем

- Пишет коротко, иногда с опечатками; отвечать по делу, без длинных списков проделанного.
- Если просит «новую версию» — делать новую; если говорит «правь последнюю» — править текущую.
- Перед выкладкой проверять страницу; после выкладки сказать, что сайт обновится за пару минут.
